# BACKEND REQUEST — integração frontend

1. **Distribuição**: servir `frontend/dist/index.html` em /app, monitor.html em /monitor, static/ em /static; manifest.webmanifest e sw.js na raiz. Service worker com Content-Type JavaScript e Cache-Control:no-cache. HTTPS em produção; localhost no desenvolvimento. Não dar cache público a /eu,/login,API ou imagens privadas. Sugestão de proxy em README frontend.
2. **Notificações faciais**: o painel usa `GET /presencas?limite=100&depois=<id>` para buscar eventos incrementais de `metodo_identificacao=facial`. O frontend estabelece uma linha de base ao entrar, mostra até oito cartões na lateral e abre o perfil quando `aluno_id` existe. O polling não deve ser tratado como fila offline nem armazenar fotos ou templates no navegador. Contrato detalhado em [`docs/NOTIFICACOES_ACESSO_FACIAL.md`](../NOTIFICACOES_ACESSO_FACIAL.md).
3. **Região**: GET/PATCH /academia/preferencias e PATCH /eu/preferencias são somente sugestões. Necessários paísISO,endereço,cidade,estado,código postal,idioma entre5 opções,moedaISO e meios de pagamento. Não são consumidos até constarem no contrato.
4. **Financeiro**: agregado autenticado de pagamentos/receita por moeda, matrículas por data real e despesas para lucro. Atual frontend usa /pagamentos completo; contrato de paginação exigirá agregado backend antes de volumes grandes.
5. **Banco**: `015_pagamentos_online.sql` já define checkout dLocal e webhook autenticado/idempotente para a assinatura Frequency. O frontend chama `/assinatura-frequency/checkout` e redireciona para a URL HTTPS do provedor; nenhum pagamento automático é simulado por QR estático. A homologação depende de credenciais dLocal e webhook público.
6. **Offline e backup**: serviço local e banco continuam necessários para operações offline de internet. Frontend PWA guarda só assets públicos; sem API acessível, não aceita operação que pareça salva. Status de backup/sync, fila idempotente, resolução de conflitos e assinatura atualizada remotamente necessitam contrato do backend. Endpoint sugerido /operacao/status, ainda não consumido.
7. **Homologação integrada**: disponibilizar staging com dados sintéticos, HTTPS, migrações e contas por perfil. Revisar 401/402/403/409/422/429/503 e confirmação de pagamento para teste real. Não fornecer segredos em documentação.
